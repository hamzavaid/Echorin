# v1.5 — Bistatic and Multistatic Sensing

Separate mounted emitters/receivers and independent dynamic platforms now feed
the existing Radar/Sonar array, matched-filter, CA-CFAR, Bartlett, Doppler and
CV tracking pipeline. No fusion or v1.6 algorithms are included.

- Two-leg path length/delay and moving-TX/RX Doppler, analytically validated.
- Independent transmit power, waveform, beam/scan, receive array/beam/noise.
- Co-located convenience factory and bit-exact legacy acquisition tests.
- Multiple TX/RX pairs, source IDs, independent source-scoped trackers.
- Engineering dock, source selector, known device positions/headings/paths/beams.
- Half-path range/rate plots, total path/rate inspector and measured-ray
  ellipse inversion for Cartesian positioning and measurement covariance.
- Scenario schema 4; schemas 1–3 still load. Legacy worlds still write schema 3.
- Truth-free schema-2 frame recordings include optional `source_frames`; CSV
  exports every source's rows with emitter/receiver IDs and path quantities.

## Usage

Open View → Transmitters / Receivers and choose Bistatic or Multistatic, then
Load scenario. These presets replace targets/platforms and restart simulation,
scaled to the selected Radar/Sonar medium. Select a TX→RX stream to inspect its
plots and local tracks. All links are still processed in the single worker.
Track identity is `(emitter_id, receiver_id, track_id)`, not a fused global ID.

The JSON editor exposes each platform's state and existing trajectory kind,
emitter/receiver lists, body-frame mounts, device `config`, beams/scans, receiver
`array_config`, optional receiver `noise_model` override and transmit power.
Positions are metres, velocities m/s, angular fields radians and timestamps
seconds. Edited configurations must start at timestamp zero. Apply validates
the entire network and restarts; errors preserve the current configuration.
Per-device beams override the legacy beam control; the environment's clutter,
interference, absorption and multipath still affect every link. A receiver's
optional noise-model override supersedes the environment noise kind; its
sampling config's `noise_model` retains the standard deviation/SNR scale.
Global mode/noise/waveform controls update device configuration consistently
with reset. Mode changes preserve geometry; reload a medium-scaled preset if
the old scene lies outside the new medium's sampled range/Doppler interval.

## Engineering decisions and approximation limits

Emitters use explicit **time-division** CPI slots at the same simulation epoch.
Each receiver sums all point/field/path echoes for the scheduled transmitter
before DSP. There is no ideal target channel, simultaneous-source separation,
passive RF capture or orthogonal-code processing. At most 16 TX/RX pairs are
allowed. All pairs currently require compatible medium, carrier, sample rate,
bandwidth, pulse width and PRF; rectangular/LFM waveforms may differ by emitter.
This conservative compatibility gate avoids silently interpreting incompatible
signals through an incorrect matched filter. Heterogeneous scheduling is deferred.

Geometry/beam boresight are held per CPI (stop-and-hop approximation); phase
uses first-order narrowband path-rate Doppler with the established positive
increasing-path convention. Range migration, retarded-time moving geometry,
absolute carrier path phase, terrain visibility/occlusion and high-fidelity
ray tracing are not modeled. ULA front/back ambiguity remains.

Direct-path attenuation multiplies bounded inverse-power factors from each
leg, reducing to the legacy monostatic law. Secondary extra length is split
evenly between phenomenological legs and inherits direct Doppler. A single
seeded world field is anchored to the first receiver, with extent based on the
largest receiver window; all links see the same scatterers. Noise streams are
independent in stable configured link order. Saved scenes initialize a fresh
field; they are not live scatterer-state checkpoints.

Measured delay gives total path length, not receiver range. Plots retain the
legacy numeric half-path coordinate and half-path-rate FFT axis, explicitly
labeled. Detection `range_m` is inferred receiver distance from measured arrival
bearing, measured total path and known TX/RX poses. `radial_velocity_mps` is
unavailable for bistatic measurements; `path_rate_mps` stores the observable.
Impossible/baseline-degenerate ellipse cells remain visible in products but
cannot create Cartesian tracks. Multipath/clutter can still produce nuisance
tracks; there is no truth correction. The tracker remains the existing linear
Cartesian CV tracker, with ellipse-inverse measurement covariance, not an EKF.

## Reproducible validation

`python benchmarks/run_bistatic_benchmark.py` reports complete seed/config,
four frames per case, every moving TX/RX pair, analytic/measured path/rate,
bin-scaled errors, detections and all-link processing timing. Radar uses 3 km,
4 MHz carrier and 20 Hz PRF; Sonar uses 60 m, 20 kHz and 3 Hz PRF; both use
eight half-wavelength elements, 32 pulses and noise sigma 0.0001. Radar settings
make nonzero Doppler observable rather than relying on the default coarse bins.
Acceptance: path error ≤ one `c/fs` bin, bearing error ≤ one degree and total
path-rate error ≤ one `lambda*PRF/N` bin on every frame and source. Repeated
seeded runs must produce identical measurements. No brittle wall-clock CI gate.

[Numerical evidence](../../benchmarks/bistatic_validation.svg) and
[workspace capture](../../screenshots/echorin-multistatic.png) are generated by
`python examples/capture_bistatic_demo.py`. Its Sonar GUI uses 16 pulses, while
the numerical benchmark uses 32. The single-worker bounded queue preserves
interaction regardless of processing duration; simulation does not catch up
to wall time. Larger windows, arrays, clutter or 16-link networks can reduce
update rate and use substantial memory.

On the Windows/Python 3.14 reference machine, four-link GUI capture totals were
about 44–45 ms in Radar (32 pulses) and 566–643 ms in Sonar (16 pulses), meeting
local release-view budgets of 250 ms and 1 s respectively. The full 32-pulse
four-link numerical benchmark took approximately 36 ms in Radar and 898–971 ms
in Sonar. These are configuration-specific observations, not hardware guarantees
or limits on the user's simulation timestep. The worker heartbeat remains live
even when computation exceeds the selected update interval.

All 219 automated tests and Ruff pass in the project environment and a fresh
non-editable wheel installation with current dependencies. Native Windows Qt
launches published frames for legacy and multistatic scenes in both Radar and
Sonar. Public figures/captures were visually checked. Internal handoff documents
and specifications remain ignored and absent from tracked history/the wheel.
Remote cross-platform CI has not been run by this local release verification.
